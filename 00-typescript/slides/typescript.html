למה TypeScript: אותו באג, פעמייםWhy TypeScript: the same bug, twice

מחיר שהגיע מטופס כמחרוזת. JavaScript לא מתלונן, TypeScript עוצר לפני שהקוד רץA price that came from a form as a string. JavaScript doesn’t complain, TypeScript stops it before the code runs

JavaScript: הבאג מתגלה אצל המשתמשJavaScript: the user finds the bug

function total(items) {
  return items.reduce(
    (sum, i) => sum + i.price, 0
  );
}

total([{ name: "Pen", price: "5" }]);
// "05"  ← a string, no error

TypeScript: הבאג מתגלה בעורךTypeScript: the editor finds the bug

type Item = { name: string; price: number };

function total(items: Item[]): number {
  return items.reduce(
    (sum, i) => sum + i.price, 0
  );
}

total([{ name: "Pen", price: "5" }]);
// error: Type 'string' is not
//   assignable to type 'number'.

אובייקטים: type ו-interfaceObjects: type and interface

מתארים איך נראה אובייקט: אילו שדות יש בו, ומה הטיפוס של כל אחדDescribe an object’s shape: which fields it has, and the type of each

type User = {
  id: number;
  name: string;
  email?: string;           // optional
  readonly createdAt: Date; // can't change
};

const u: User = {
  id: 1,
  name: "Dana",
  createdAt: new Date(),
};                          // email may be missing
// The same, with interface
interface User {
  id: number;
  name: string;
}
interface Admin extends User {
  permissions: string[];
}

// Or with type
type Admin = User & { permissions: string[] };

צמצום טיפוסים (Narrowing)Narrowing

אחרי בדיקה עם if, TypeScript יודע איזה טיפוס נשאר. זה מה שהופך את undefined לבטוחAfter an if check, TypeScript knows which type is left. That’s what makes undefined safe

הקלאסיקה: find מחזיר אולי undefinedThe classic: find may return undefined

const recipe = recipes.find(
  (r) => r.id === id
);
// recipe: Recipe | undefined

recipe.title;
// error: 'recipe' is possibly 'undefined'.

if (!recipe) return null;
recipe.title;   // OK: recipe is Recipe now

recipe?.title;              // or optional chaining
recipe?.title ?? "Untitled";  // with a fallback

בדיקה עם typeofChecking with typeof

function format(value: string | number) {
  if (typeof value === "number") {
    return value.toFixed(2);
    // value: number here
  }
  return value.toUpperCase();
  // value: string here
}
לא להשתיק עם !Don’t silence it with !

recipe!.title מעלים את השגיאה, אבל הקוד עדיין יקרוס אם אין מתכוןrecipe!.title hides the error, but the code still crashes if there’s no recipe

Generics: טיפוס כפרמטרGenerics: a type as a parameter

פונקציה אחת שעובדת עם כל טיפוס, ושומרת עליו. T הוא משתנה של טיפוסOne function that works with any type and keeps it. T is a type variable

לכתוב genericWriting a generic

function first<T>(items: T[]): T | undefined {
  return items[0];
}

const n = first([1, 2, 3]);
// n: number | undefined

const s = first(["a", "b"]);
// s: string | undefined

type ButtonProps = {
  label: string;
  variant?: "primary" | "secondary";
  onClick: () => void;
};

export default function Button({
  label,
  variant = "primary",
  onClick,
}: ButtonProps) {
  return (
    <button className={variant} onClick={onClick}>
      {label}
    </button>
  );
}
// Using it

// error: Property 'onClick' is missing

//   required in type 'ButtonProps'.

any מול unknownany vs. unknown

שניהם אומרים ״לא יודע מה זה״. ההבדל: מה TypeScript מרשה לעשות עם הערךBoth say “I don’t know what this is”. The difference: what TypeScript lets you do with the value

any

מכבה את הבדיקה. הכל מותרTurns checking off. Anything goes

const a: any = JSON.parse(text);
a.foo.bar();
// no error, crashes at runtime

unknown

חייבים לבדוק לפני כל שימושYou must check before any use

const u: unknown = JSON.parse(text);
u.foo;
// error: 'u' is of type 'unknown'.

if (typeof u === "string") {
  u.toUpperCase();   // OK
}

כשלא יודעים מה הגיע: unknown, ואז בודקיםWhen you don’t know what arrived: unknown, then check
