# תרגילים: Node.js, MongoDB ואימות משתמשים

כל התרגילים בונים פרויקט אחד שגדל: **auth-api**, שרת Express שמחובר ל-MongoDB, עם הרשמה, התחברות, טוקן ב-cookie ופתקים אישיים.
A.1 עד A.9 בונים את השרת צעד אחרי צעד. A.10 מחבר אליו אתר Next.js.

**לפני שמתחילים:**

- Node.js 22 ומעלה (`node -v`)
- MongoDB: אחד מהשניים
  - **Atlas** (בענן, חינם): יוצרים cluster, משתמש מסד ב-Database Access, ומוסיפים את ה-IP שלכם ב-Network Access
  - **Docker** (מקומי): `docker run -d --name mongo -p 27017:27017 mongo`
- התוסף **REST Client** ב-VS Code, לבדיקת הבקשות בקובץ `requests.http`

## A.1 · פרויקט וחיבור ל-MongoDB 🟢

**המטרה:** שרת Express שעולה רק אחרי שהוא מחובר למסד.

1. צרו תיקייה `auth-api`, הריצו `npm init -y` ו-`npm pkg set type=module`.
2. התקינו: `express mongoose bcryptjs jsonwebtoken cookie-parser cors`.
3. צרו `.env` עם `PORT`, `MONGODB_URI` (עם שם מסד בסוף, למשל `/auth-api`) ו-`JWT_SECRET`.
   צרו גם `.env.example` בלי ערכים אמיתיים, והוסיפו `.env` ו-`node_modules` ל-`.gitignore`.
4. בנו את המבנה: `src/server.js` (חיבור והאזנה), `src/app.js` (ה-app של Express), `src/config/db.js` (פונקציה `connectDB(uri)`).
5. הוסיפו `GET /health` שמחזיר `{ "status": "ok", "db": "connected" }`.
   את מצב החיבור קוראים מ-`mongoose.connection.readyState` (1 = מחובר).
6. אם חסר `MONGODB_URI` או `JWT_SECRET`, השרת מדפיס הודעה ברורה ויוצא עם `process.exit(1)`.
7. הוסיפו script: `"dev": "node --env-file=.env --watch src/server.js"`.

**בדיקה:**

- `npm run dev` מדפיס שהחיבור הצליח ושם המסד.
- `GET /health` מחזיר `db: "connected"`.
- מחקו זמנית את `JWT_SECRET` מ-`.env`: השרת לא עולה ומסביר למה.
- שנו את הפורט ב-URI ל-27018: מה השגיאה? (בדקו בטבלת התקלות במצגת)

## A.2 · משחקים עם bcrypt 🟢

**המטרה:** להבין מה זה hash לפני שמשתמשים בו.

צרו קובץ `playground/bcrypt.js` (מחוץ ל-`src`) ובו:

1. עשו `bcrypt.hash` לאותה סיסמה פעמיים, והדפיסו את שתי התוצאות. האם הן זהות?
2. הריצו `bcrypt.compare` על שתיהן עם הסיסמה הנכונה, ועם סיסמה שגויה.
3. סמנו בתוך ה-hash את הגרסה, את העלות ואת ה-salt.
4. מדדו כמה זמן לוקח `hash` עם עלות 10, 12 ו-14 (`performance.now()`).

**שאלות לחשיבה (כתבו תשובה בהערה בקובץ):**

- למה שני ה-hash שונים, ובכל זאת `compare` מצליח עם שניהם?
- למה זה **טוב** ש-hash עם עלות 14 איטי?
- מה ההבדל בין hash להצפנה?

## A.4 · הרשמה 🟡

**המטרה:** `POST /api/auth/register`.

1. צרו `src/routes/auth.js` וחברו אותו ב-`app.js` תחת `/api/auth`.
2. הנתיב מקבל `{ name, email, password }` ומחזיר:

   | מקרה | סטטוס |
   |------|-------|
   | שם חסר, אימייל לא תקין, סיסמה קצרה מ-8 תווים | 400 עם הודעה ברורה |
   | האימייל כבר רשום | 409 |
   | הצלחה | 201 עם `{ user }`, **בלי** ה-hash |

3. נקו את האימייל (רווחים ואותיות גדולות) **לפני** הבדיקה.
4. צרו `requests.http` עם בקשה לכל אחד מהמקרים בטבלה.

**בדיקה:** הירשמו עם `" Dana@Example.com "` ואחר כך עם `"dana@example.com"`. השנייה צריכה לקבל 409.

## A.5 · התחברות ו-JWT 🟡

**המטרה:** `POST /api/auth/login` שמחזיר טוקן, ונתיב מוגן ראשון.

1. צרו `src/lib/tokens.js` עם `signToken(user)` ו-`verifyToken(token)`.
   ב-payload: `sub` (מזהה המשתמש) ו-`role`. תפוגה: 7 ימים.
2. נתיב ההתחברות:
   - 400 אם חסר אימייל או סיסמה
   - 401 עם **אותה הודעה בדיוק** כשהאימייל לא קיים וכשהסיסמה שגויה
   - 200 עם `{ user, token }` כשהכול תקין (בשלב הזה הטוקן בגוף התשובה)
3. צרו `src/middleware/requireAuth.js` שקורא את הטוקן מה-header `Authorization: Bearer <token>`,
   בודק אותו, טוען את המשתמש ושם אותו ב-`req.user`. בלי טוקן או עם טוקן לא תקין: 401.
4. הוסיפו `GET /api/auth/me` שמוגן ב-`requireAuth` ומחזיר את המשתמש.

**בדיקה:**

- ב-`requests.http` שימו את הטוקן במשתנה, ושלחו `/me` עם ה-header.
- פענחו את ה-payload בלי ספרייה, ב-Node:
  `JSON.parse(Buffer.from(token.split(".")[1], "base64url").toString())`
- שנו תו אחד בחלק האמצעי של הטוקן ושלחו שוב. מה קורה?

## A.6 · הטוקן עובר ל-cookie 🟡

**המטרה:** הדפדפן שומר ושולח את הטוקן לבד, ו-JavaScript לא יכול לגנוב אותו.

1. הוסיפו `cookieParser()` ב-`app.js`.
2. בהרשמה ובהתחברות: שמרו את הטוקן ב-cookie בשם `token` עם
   `httpOnly: true`, `sameSite: "lax"`, `secure` רק ב-production, ו-`maxAge` של 7 ימים.
   הוציאו את `token` מגוף התשובה.
3. `requireAuth` קורא קודם מה-cookie, ואם אין, מה-header `Bearer` (בשביל Postman ומובייל).
4. הוסיפו `POST /api/auth/logout` שמוחק את ה-cookie ומחזיר 204.

**בדיקה:**

- ב-`requests.http`: התחברו, ואז `/me` עובד **בלי** header.
- בתשובה להתחברות, מצאו את `Set-Cookie` וזהו כל אחת מהאפשרויות.
- התנתקו, ו-`/me` מחזיר 401.

## A.7 · פתקים עם בעלות 🟡

**המטרה:** כל משתמש רואה ומוחק רק את הפתקים שלו.

1. צרו מודל `Note`: `text` (חובה, עד 500 תווים), `owner` (ObjectId שמפנה ל-User, חובה), `timestamps`.
2. צרו `src/routes/notes.js` תחת `/api/notes`, וכל הנתיבים בו מוגנים (`router.use(requireAuth)`):
   - `GET /`: רק הפתקים שלי, החדש ראשון
   - `POST /`: יוצר פתק. ה-`owner` נלקח מ-`req.user`, **לא** מגוף הבקשה
   - `DELETE /:id`: 404 אם אין פתק כזה, 403 אם הוא לא שלי, 204 אם נמחק
3. מזהה לא תקין (`/api/notes/123`) צריך להחזיר 400, לא 500.

**בדיקה עם שני משתמשים:** דנה יוצרת פתק. אבי מתחבר ומנסה למחוק אותו: 403. אבי גם לא רואה אותו ברשימה שלו.
(רמז: ב-REST Client אפשר לשלוח cookie ידנית, או להשתמש ב-Bearer לאחד המשתמשים)

## A.8 · תפקידים: admin 🟡

**המטרה:** הרשאות לפי תפקיד.

1. כתבו `requireRole(role)`: פונקציה שמחזירה middleware, ומחזירה 403 אם לתפקיד של המשתמש אין הרשאה.
2. כתבו סקריפט `scripts/create-admin.js <email> <password> [name]` שיוצר admin, או הופך משתמש קיים ל-admin.
   (אין נתיב הרשמה שמאפשר לבחור `role`. למה?)
3. צרו `src/routes/admin.js` תחת `/api/admin`, מוגן ב-`requireAuth` וב-`requireRole("admin")`:
   - `GET /users`: כל המשתמשים, בלי hash
   - `PATCH /users/:id/role`: מקבל `{ role }`, רק `"user"` או `"admin"`
4. עדכנו את מחיקת הפתק: admin יכול למחוק כל פתק.

**בדיקה:** משתמש רגיל מקבל 403 על `/api/admin/users`. בלי התחברות: 401.
נסו להירשם עם `"role": "admin"` בגוף הבקשה. האם זה עבד? (זה לא אמור לעבוד)

## A.9 · הקשחה ובדיקות אוטומטיות 🔴

**המטרה:** להפוך את ה-API לבטוח יותר, ולהוכיח שהוא עובד בבדיקות.

1. **הגבלת ניסיונות:** עם `express-rate-limit`, אחרי 5 ניסיונות התחברות **כושלים** ב-15 דקות, מחזירים 429.
   התחברויות מוצלחות לא נספרות.
2. **טוקן שפג:** כשהטוקן פג, ה-401 כולל `code: "TOKEN_EXPIRED"`. טוקן מזויף מקבל `code: "INVALID_TOKEN"`.
3. **החלפת סיסמה:** `POST /api/auth/change-password` עם `{ currentPassword, newPassword }`.
   אחרי ההחלפה, **כל הטוקנים הישנים** מפסיקים לעבוד (גם במכשירים אחרים).
   רמז: שדה `tokenVersion` במשתמש, שנכנס גם ל-payload ונבדק ב-`requireAuth`.
4. **טיפול בשגיאות:** middleware אחד בסוף `app.js` שממפה:
   `ValidationError` ל-400, `CastError` ל-400, קוד `11000` ל-409, JSON שבור ל-400, וכל השאר ל-500 (בלי לחשוף פרטים).
5. **בדיקות:** עם `node:test` ו-`supertest`, על מסד בדיקות נפרד. כסו לפחות:
   - הרשמה מחזירה 201, cookie עם `HttpOnly`, ובלי hash בתשובה
   - אימייל כפול מחזיר 409
   - אותה הודעת 401 לאימייל לא קיים ולסיסמה שגויה
   - טוקן ששונה בו ה-payload נדחה
   - משתמש לא יכול למחוק פתק של משתמש אחר
   - אחרי החלפת סיסמה, הטוקן הישן מקבל 401

**בונוס:** אם המשתמש לא קיים, ההתחברות חוזרת מהר יותר (אין `bcrypt.compare`). מדדו את זה. איך היה אפשר לסגור את הפער?

## A.10 · אתר Next.js מחובר 🔴

**המטרה:** אתר אמיתי שמשתמש ב-API.

1. צרו פרויקט Next.js חדש (`npx create-next-app@latest auth-web`). הוא רץ על 3000, ה-API על 4000.
2. ב-API: `cors` עם `origin: "http://localhost:3000"` ו-`credentials: true`.
3. צרו `lib/api.ts`: פונקציה אחת שעוטפת `fetch`, עם `credentials: "include"`, ושזורקת שגיאה עם הסטטוס וההודעה מהשרת.
4. דפים:
   - `/register` ו-`/login`: טופס, הודעת שגיאה מהשרת, ומעבר ל-`/notes` בהצלחה. (רמז: קומפוננטת טופס אחת עם `mode`)
   - `/notes`: טוען את `/auth/me` ואת הפתקים. אם מקבלים 401, עוברים ל-`/login`.
     אפשר להוסיף פתק, למחוק פתק ולהתנתק.

**בדיקה:**

- נכנסים ל-`/notes` בלי להתחבר: עוברים ל-`/login`.
- נרשמים, ומגיעים לפתקים. ב-Console כותבים `document.cookie`: הטוקן **לא** מופיע. ב-DevTools ← Application ← Cookies הוא כן מופיע, עם HttpOnly.
- מרעננים את הדף: עדיין מחוברים.
- מתנתקים, ואז חוזרים אחורה בדפדפן: עוברים שוב ל-`/login`.
- מורידים זמנית את `credentials: "include"`. מה נשבר, ואיפה רואים את זה ב-Network?
